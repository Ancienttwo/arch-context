## Design Decisions
**(a) Additive freeze, mechanical promotion.** RF4 decision (b) deferred `RefactorVerificationRequestV1` to this row so the type is frozen in the same release that first accepts it over JSON. Field set is exactly RF4's `RuntimeRefactorVerifyInput`; promotion is a type-alias swap plus ingress validation. Any temptation to add fields (e.g. `expectedOutcomes` override) is out of scope: the recommendation already carries them and a caller-supplied override would let the Agent steer the verdict.

**(b) `--request-json` required for `verify`.** Unlike `scan` (repository default), verify has no default subject. Missing flag ⇒ `AC_SCHEMA_INVALID` with message `--request-json is required`. `--recommendation-id <id>` shortcut is a PRD "Freedom"; implement only if it is one line of sugar over the same object — never a second parsing path.

**(c) Same pin-sweep scoping as RF5a, plus two known non-pins.** `rg -n --fixed-strings '0.5.0' --glob '!CHANGELOG*' --glob '!docs/**' --glob '!deploy/**' --glob '!plans/**' --glob '!tasks/**' --glob '!.claude/**' --glob '!_ops/**' --glob '!_ref/**' --glob '!bun.lock'` must be empty **except** `scripts/fg5-full-plane-dlp-readback.ts` if its `runtimeVersion: "archctx/0.5.0"` literals are confirmed synthetic fixture values (they predate 0.5.0 on main, so they are not product pins). `bun.lock` matches are third-party `^0.5.0` semver ranges. Record both exclusions in the notes; do not "fix" them.

**(d) Budgets.** Surfaces after RF5a ≈ 6.3k lines / 12 files (bucket 5000–10000 / 10–20); `verify` adds ~80 lines. local-runtime after RF4 ≈ 15 files / ~20.9k (10–20 / 20k–50k). Contracts adds ~60 lines. No bucket flips expected ⇒ no `docs apply`; if `docs plan --json` reports owned drift, regenerate via `docs apply --approved` on a clean tree after the last commit and stop on `human-action-required`.

**(e) Smoke timing.** `refactor verify` re-scans at HEAD; the smoke repo has two nodes, so it is well under the 30 s per-process timeout. Do not raise `PROCESS_TIMEOUT_MS`.
