# Manifest content-path correction — issue #171

Baseline: `901e4b8`.

The manifest's declared ADR location was `.archcontext/decisions`, but the active ADR loader `loadArchitectureDecisionRecords` reads `docs/adr`. The initializer's default manifest now declares `docs/adr`; the loader and existing ADR files remain the same authority.

The initializer fix left existing manifests unchanged: a normal daemon `planUpdate`/`applyUpdate` attempt rejected `.archcontext/manifest.yaml` as outside the generic ChangeSet write allowlist. The approved continuation below supplies the missing controlled mutation contract and corrects this repository through it.

The practices entry has different semantics: `.archcontext/practices` is an optional repository overlay. `loadRepoOverlayAssets` returns an empty overlay when it does not exist. Built-in practices come from `packages/core/practice-catalog/assets/practices`, selected by `BUILTIN_PRACTICE_ASSETS_DIR`. Pointing the overlay entry at those built-ins or adding placeholder data would misrepresent that boundary. An absent overlay directory is valid and remains absent here.

Likewise, an initialized project may have no ADRs yet; the loader returns no records until `docs/adr` exists. These paths declare content locations, not required nonempty directories. This correction does not introduce configurable directory routing or change the fixed loaders. `tsconfig.json` already has no `apps/**` include at this baseline.

Initializer-only validation: the existing model-store, ADR projection and practice-catalog tests passed (42 tests, 160 assertions), and typecheck passed. A temporary initialized project declared `docs/adr`; the ADR loader read a record written there, and the catalog loaded without errors while the repository overlay remained absent. That initial slice changed no persistence layout or write path. At larger repository size, the existing ADR/overlay directory scans remain the cost.

## Approved existing-manifest correction

P1: `changeset-engine` owns writes, journal and rollback; daemon `planUpdate`/`applyUpdate` supplies repository/HEAD/worktree/model freshness and serialized writer ownership. CLI and MCP are triggers. `projection-engine` and `architecture-domain` still read/validate ADRs at the fixed `docs/adr` location. The manifest is a declaration, not configurable ADR routing.

P2: `archctx manifest plan --id changeset.ID --decisions docs/adr` reads the existing manifest and creates `update_manifest_fields` with its expected hash. Existing daemon preview checks the exact path, operation shape, explicit YAML schema/content field and existing non-symlink ADR directory. `archctx apply --id changeset.ID --expected-worktree-digest <preview base digest> --approved` rechecks freshness, renders the single supported field, journals and atomically writes it. Failed writes restore the preimage. MCP uses the same operation schema and requires the existing CLI-issued one-time approval token. Durable journal readback recognizes the operation; dual mode hashes field metadata and appends ledger events through the existing daemon transaction.

P3: the operation must be the only operation in its ChangeSet. It accepts exactly `.archcontext/manifest.yaml`, an existing-file SHA256 hash, and `{ "content.decisions": "docs/adr" }`; body, arbitrary fields/paths/values and mixed drafts fail closed. The generic allowlist is unchanged. YAML Document editing preserves comments and unrelated values, rejects duplicate/ambiguous input and alias changes to unrelated settings, and does not regenerate projections. No arbitrary configuration editor, fallback reader, directory migration or new authority is introduced. Full model validation/import remains the first scaling cost across 10x repositories; this bounded correction needs no cache.

The actual repository update succeeded through the production CLI/daemon under ChangeSet `changeset.manifest-decisions-171`, with an exact one-scalar diff. Current repository mode remains `yaml`; dual-ledger behavior was verified separately by RPC integration tests. Readback: `docs/verification/20260925-manifest-fields-readback.json`. The temporary daemon was stopped through the normal CLI afterward.
