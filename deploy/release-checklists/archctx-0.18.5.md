# archctx / archctx-contracts 0.18.5 preparation

The release covers the commits after `v0.18.4` (`28892c91`) through `460b2642` on `main`.
The patch bump ships Node.js 26 LTS support from #655: the supported engine range widens from `>=22.22 <26` to `>=22.22 <27` and CI runs the Node compatibility jobs on Node 26.x. [#655](https://github.com/Ancienttwo/arch-context/issues/655) [PR #656](https://github.com/Ancienttwo/arch-context/pull/656)

## Release notes

archctx 0.18.5 adds Node.js 26 LTS to the supported runtime range. The product behaviour on Node.js 22.22, 24 and 25 is unchanged.

- **Wider engine range:** `engines.node` in `package.json` and `ARCHCONTEXT_NODE_RANGE` in `@archcontext/contracts` become `>=22.22 <27`. The CLI entry check reads the same constant, so a Node 26 process no longer exits with `AC_NODE_VERSION_UNSUPPORTED`, and `archctx doctor` reports `hardening.supportedNode` as supported there. [#655](https://github.com/Ancienttwo/arch-context/issues/655) [PR #656](https://github.com/Ancienttwo/arch-context/pull/656)
- **Node 26 in CI coverage:** the node compatibility family adds Node `26.x` on `ubuntu-latest`, `macos-15` and `windows-latest`, so `bun run verify:node-compat` and the platform IPC permission readback now run on three newer Node major versions instead of two. Release validation grows from 28 jobs to 31. [#655](https://github.com/Ancienttwo/arch-context/issues/655) [PR #656](https://github.com/Ancienttwo/arch-context/pull/656)

### Compatibility notes

Upgrade `archctx` and `archctx-contracts` together. No JSON schema body, failure reason code, RPC schema or SQLite migration changed from 0.18.4.

- The published `product-version-manifest` schema's `engines.node` `const` changes from `>=22.22 <26` to `>=22.22 <27`, and the `archcontext.capabilities/v1` fixture carries the new product version. A manifest produced by 0.18.4 does not validate against the 0.18.5 schema, and the reverse also fails, so a consumer that validates manifests must take both packages from the same version. [PR #656](https://github.com/Ancienttwo/arch-context/pull/656)
- `nodeVersionSatisfiesRange` now accepts `26.x` and refuses `27.0.0` and later. A workflow that pinned `archctx` to a Node version outside `>=22.22 <27` fails the same way as before. [PR #656](https://github.com/Ancienttwo/arch-context/pull/656)

## Rollback

Before publication, run `git revert <squash-commit>` to restore the 0.18.4 version authorities and the `>=22.22 <26` engine range. Once an upload is accepted, wait for registry visibility. Published versions are immutable, so a fix after publication needs a new version.
