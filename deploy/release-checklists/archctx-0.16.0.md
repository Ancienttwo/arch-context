# archctx / archctx-contracts 0.16.0 preparation

The release covers `v0.15.0` through `beffc36d` on `main`.
The minor bump reflects the published `CodeFactsPort` changes in #610.

## Release notes

archctx 0.16.0 can seed a fresh linked worktree from a shared CodeGraph base index. Run `archctx sync` in the primary checkout to publish the base, then run `archctx sync` in the linked worktree. `prepare`, `complete`, projection commands that build a snapshot, and `flows check` with sync enabled can also seed. [#610](https://github.com/Ancienttwo/arch-context/pull/610)

- The primary checkout takes a SQLite snapshot after a successful sync. A linked worktree syncs a private copy under the command's deadline and checks index compatibility, completeness, and freshness by full content hash before installing it. An existing worktree database is never replaced by a seed.
- Seeding requires the pinned CodeGraph bundle and an eligible `.codegraph` layout. Windows, a `CODEGRAPH_DIR` override, or a named CodeGraph binary disables it. If no base is available or the seed is declined, use `codegraph init` in that worktree. A first base build in progress can return the retryable `index-base-building` reason under `AC_CODE_FACTS_UNAVAILABLE`.
- Read-only paths verify the requested worktree's own index and leave sync to commands that own it. Run `archctx sync` when a read reports that code facts are unavailable or out of date.
- `archctx sync` can report `codeGraphBase` with the base refresh outcome and `codeGraphKept` with paths left for manual cleanup, such as old snapshots, abandoned staging directories, stale locks, and unproven pointers. A base refresh failure is reported without failing the sync.
- The repository's harness scripts and reference docs now use the `rh` command name. [#607](https://github.com/Ancienttwo/arch-context/issues/607)

### Compatibility notes

Upgrade `archctx` and `archctx-contracts` together.

- Replace implementations and calls of `CodeFactsPort.assertCanSync(workspaceRoot)` with `prepareSync(workspaceRoot)`. The new hook can seed a missing index before checking compatibility.
- Pass `workspace` in the input to `CodeFactsPort.buildTaskContext` and as the second argument to `CodeFactsPort.findSymbols`. Ensure readiness or sync that workspace before reading. `ensureReady(workspace)` verifies read-only. A caller that owns a sync can pass `{ syncOnMiss: true }` to sync a workspace the port has yet to verify.
- `CodeFactsSnapshot` adds optional `codeGraphBase` and `codeGraphKept` fields, with public `CodeGraphBaseRefreshV1` and `CodeGraphKeptPathV1` types. Consumers of failure envelopes can handle the new retryable `index-base-building` reason. The `index-missing` message now includes linked-worktree recovery guidance.
