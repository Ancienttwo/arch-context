# archctx / archctx-contracts 0.17.0 preparation

The release covers the commits after `v0.16.0` through `c0cf6ec1` on `main`.
The minor bump adds CLI commands and published contracts for the #617 batch. [#617](https://github.com/Ancienttwo/arch-context/issues/617)

## Release notes

archctx 0.17.0 adds single-pass pull request verification, batch impact reports, native debt deltas, and read-only architecture slices.

- `archctx verify --base <ref> --json` uses one worktree model load and one read-only CodeGraph session to report model validation, flows, state machines, constraints, doc anchors, projection checks, and debt. The response includes a result or producer error for each check. [#618](https://github.com/Ancienttwo/arch-context/issues/618) [PR #627](https://github.com/Ancienttwo/arch-context/pull/627)
- `archctx impact --batch-file <json-path> --json` runs multiple changed-path queries against one loaded model and returns results in input order. Items that exceed the remaining 8 MiB response budget report `batch-response-bytes`, and later items can still fit. [#618](https://github.com/Ancienttwo/arch-context/issues/618) [PR #627](https://github.com/Ancienttwo/arch-context/pull/627)
- `archctx refactor scan --node <id>` includes files owned by a node and its descendants. Repeatable `--path` flags scan selected paths. Both measure incident imports and direct neighbors and return open recommendations alongside new candidates. Pass the scan's `data.snapshotDigest` as `--snapshot-digest` to `archctx recommendations accept`, `defer`, or `reject` to reuse the structural snapshot while it remains in the daemon cache. [#619](https://github.com/Ancienttwo/arch-context/issues/619) [PR #625](https://github.com/Ancienttwo/arch-context/pull/625)
- `archctx debt --base <ref> --json` compares the working tree with a Git commit and reports introduced items, resolved IDs, and coverage for both sides. The repository-shared SQLite base cache keys reports by commit, model tree, engine versions, and measurement profile. Use `--complete` to select the complete measurement profile for both sides. [#620](https://github.com/Ancienttwo/arch-context/issues/620) [PR #624](https://github.com/Ancienttwo/arch-context/pull/624)
- `forbid-dependency` rules can declare `rule.allowedTargets` for public contract subtrees. Each allowed node must be a strict descendant of a forbidden target, and all owners of the imported file must be within allowed subtrees for the exemption to apply. [#621](https://github.com/Ancienttwo/arch-context/issues/621) [PR #623](https://github.com/Ancienttwo/arch-context/pull/623)
- `archctx projection slice --base <ref>` renders a read-only pull request slice from the merge base through HEAD. Markdown includes a highlighted Mermaid diagram and declared module entrypoint anchors. JSON includes the resolved revisions. The command requires a clean tracked checkout and fresh CodeGraph facts. [#622](https://github.com/Ancienttwo/arch-context/issues/622) [PR #626](https://github.com/Ancienttwo/arch-context/pull/626)
- Explorer keeps fresh, unpinned graph baselines readable by digest within the cache's age, entry, and byte limits. This preserves the first graph delta after a ledger event in the same authority scope. [#615](https://github.com/Ancienttwo/arch-context/issues/615) [PR #616](https://github.com/Ancienttwo/arch-context/pull/616)

### Compatibility notes

Upgrade `archctx` and `archctx-contracts` together.

- The contracts package adds schemas and fixtures for verify, impact batch requests and responses, debt deltas, and projection slices. Verify's `validate` result measures worktree YAML even when standalone `validate` uses the authoritative ledger. [PR #627](https://github.com/Ancienttwo/arch-context/pull/627)
- Dependency constraint consumers can receive an `undetermined` result with reason `forbid-target-unowned` when a rule with `allowedTargets` applies to a resolved import whose target file has no owner. [PR #623](https://github.com/Ancienttwo/arch-context/pull/623)
- Scoped refactor measurements can persist `observationScopeDigest` in decision files. The 0.16.0 parser rejects that field. Use a compatible checkout if you downgrade. `archctx refactor verify` reports `baseline-snapshot-scope-mismatch` when it compares a repository-wide measurement with a scoped baseline. [PR #625](https://github.com/Ancienttwo/arch-context/pull/625)
