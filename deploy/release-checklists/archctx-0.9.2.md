# archctx 0.9.2 release checklist

Status: preparation only. The target pair is `archctx@0.9.2` and `archctx-contracts@0.9.2`.
The latest published release is [archctx 0.9.1](https://github.com/Ancienttwo/arch-context/releases/tag/v0.9.1),
published 2026-10-22 with `archctx-0.9.1.tgz`, `archctx-contracts-0.9.1.tgz` and `SHA256SUMS`.
The npm registry lists 0.9.1 as the latest version of both packages. No 0.9.2 tag, release or upload exists.

## Changes

[#400](https://github.com/Ancienttwo/arch-context/pull/400) fixes [#399](https://github.com/Ancienttwo/arch-context/issues/399).
A downstream repository that ignored `/.archcontext/` lost its only model copy. Its committed projection
manifest then made `docs adopt` fail with `projection-manifest-upgrade-required` and no usable next step.

- `projection-manifest-upgrade-required` now names `archctx docs apply --approved --profile <default|repo-harness/v1>`
  and the projection runbook. It states that the model must be restored first and that the manifest digest cannot recover it.
- `ignoredRepositoryPaths` asks `git check-ignore --verbose --no-index` which model paths, and which model files present
  under them, the ignore rules exclude. `--no-index` judges the rules alone, so a force-added file does not hide an
  ignored directory. File rules such as `.archcontext/model/nodes/*.yaml` are caught too.
- `archctx status` adds `architectureModelIgnoredPaths` (`path`, `source`, `line`, `pattern`) when a model path is excluded.
- `archctx docs adopt` and `projection run` in `adopt` mode refuse before they render with `AC_PRECONDITION_FAILED`,
  `reasonCode: "architecture-model-ignored"` and `action: "commit-architecture-model"`. `details.commands` holds the
  `git check-ignore` command that prints each deciding rule.
- The projection runbook and quickstart list the paths to commit: `.archcontext/manifest.yaml`, `product.yaml`,
  `model/nodes|relations|flows/`, `decisions/`, `policies/`, `practices/` and `projections/`.

[#403](https://github.com/Ancienttwo/arch-context/pull/403) is phase 1 of [#402](https://github.com/Ancienttwo/arch-context/issues/402):
a layered architecture view and a runtime topology view generated by archctx itself. Phase 2 is not part of this release.

- Nodes get an optional `layer` field (slug). One function, `architectureLayerGroups`, feeds every exporter: Mermaid
  renders one `subgraph` per layer, LikeC4 renders view groups, Structurizr sets the element `group`. The `parent`
  chain is not used for layers because it already drives capability ownership and footprint roll-up.
- New node kinds `process`, `namespace` (with `namespace.type`) and `mount` (with `mount.target`, `mode`, `order` and an
  optional `source`). Schema rules require each object on its own kind and reject it on any other kind.
- New relation kinds `spawns`, `runs-in` and `mounts`. They declare no capability dependency.
- `runtimeTopologyModelIssues` checks relation endpoint kinds, allows one namespace per process and one mounter per mount,
  and requires namespace parents to be namespaces. It runs in `YamlModelStore.validateModel`, in native-context
  validation and in the renderer, and fails closed in all three.
- New projection target types `diagram-runtime-topology` (`docs/architecture/diagrams/runtime-topology.mmd`) and
  `runtime-topology-summary` (`docs/architecture/runtime-topology.md`). They exist only when the model has topology
  nodes. Topology nodes get no entity-summary pages. The renderer version is unchanged.
- A model without `layer` or topology data renders byte-identical output.
- Decisions are recorded in ADR-0049.

## Compatibility

Upgrade `archctx` and `archctx-contracts` together. Runtime RPC stays v2, and no dependency changes
(neither #400 nor #403 touches a `package.json` or `bun.lock`).

From #400: `architecture-model-ignored` is a new registered failure reason, and `status` gains one optional field.
A repository whose ignore rules exclude a model path can no longer run `docs adopt` until it fixes the rule.
That refusal is intended: adoption commits documents and a manifest that name an uncommitted model only by digest.
Other `docs` actions, `complete` and the projection writer are unchanged.

From #403, additive schema changes:

- Repo schemas gain the optional node `layer`, the node kinds `process`, `namespace` and `mount` with their
  `namespace` and `mount` objects, and the relation kinds `spawns`, `runs-in` and `mounts`.
- Runtime projection schemas gain the target types `diagram-runtime-topology` and `runtime-topology-summary`.
- `archctx-contracts` adds `runtimeTopologyModelIssues` and the layered and runtime-topology fixtures.
- A model without `layer` or topology data is unaffected and renders byte-identical output.
- A model that uses the new fields requires 0.9.2 on every reader: an older `archctx` rejects it at schema validation.
  Upgrade `archctx` and `archctx-contracts` together, and downstream (repo-harness) must not author topology or layers
  before pinning 0.9.2.
- Phase-1 limitation: a `namespace` node with `source.include` fails the docs projection with
  `projection-footprint-uncovered` until phase 2 gives topology targets their own source stamps. A test pins this and
  ADR-0049 records it.
- LikeC4 output for `group` and the new element kinds was checked against the upstream grammar, not with a local
  LikeC4 parser.

## Version authorities

The release PR changes the same 16 version-bound files as 0.9.1 (#396): the root and five workspace manifests,
`ARCHCONTEXT_PRODUCT_VERSION`, `bun.lock` workspace lines, the two valid version fixtures, the review action
default, the two docs/examples workflows, the practice catalog `productVersion`/`catalogDigest`, and the two
deterministic readback records (`modelDigest`, `generatedAt`). Synthetic test fixtures that name 0.9.1 are not
version authorities and stay unchanged.
