## Why

The refactor instrument PRD (`plans/prds/20260902-2312-refactor-intelligence-resolution-ledger.prd.md`, Key risk / Known Unknowns) can only judge scale as finely as the model. Today `capability.architecture-context` claims all of `packages/**/src/**`, so every proposal resolves to one node and `module` vs `cross_module` cannot be distinguished on this repo. The 5 npm workspaces and the `packages/core/*` subpath exports are already the machine-enforced boundary (`packages/*/package.json` `exports`, `scripts/package-boundary-audit.mjs:6-12`); the model should mirror them. Without this, RF2 dogfooding on this repo is impossible and the architecture docs keep describing one blob.

## Goal

Grow `.archcontext/model/nodes/` from 2 to 23 nodes through `archctx plan` / `archctx apply` ChangeSets only:

- 5 `module` nodes under `capability.architecture-context`: `module.architecture-context.{contracts,core,local-runtime,surfaces,cloud}` with `source.include` `packages/contracts/src/**` and `packages/<W>/**/src/**` respectively.
- 16 new `component` nodes under `module.architecture-context.core`, one per `packages/core/package.json` subpath export with a real `src/` (derive at execution time; expected: agent-orchestrator, application, architecture-delta, architecture-domain, architecture-ledger, changeset-engine, context-compiler, policy-engine, practice-catalog, practice-engine, pressure-engine, recommendation-engine, reconcile-engine, refactor-decision, retrieval, review-engine), `source.include` `packages/core/<S>/src/**`.
- Re-parent the existing `component.architecture-context.projection-renderer` from the capability to `module.architecture-context.core`; do not duplicate it.
- Register the 21 new nodes in `.ai/context/capabilities.json` via `repo-harness run capability-config add`, then re-project `docs/architecture` via `archctx docs plan` / `archctx docs apply` with the observed major-change reasons echoed back.

Every file under `packages/**/src/**` must resolve to exactly one deepest owner; the only overlaps are ancestor/descendant.
