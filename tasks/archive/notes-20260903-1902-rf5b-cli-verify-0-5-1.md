## Design Decisions

- `RuntimeRefactorVerifyInput` is now a type alias of `RefactorVerificationRequestV1`, so `schemaVersion`
  became a required RPC field. The daemon decoder keeps its per-field rebuild (it names the offending
  key, which the frozen validator's issue list cannot), then re-proves the rebuilt request through
  `refactorVerificationRequestInvariantIssues`. Every ingress — CLI `--request-json`, RPC dispatch,
  in-process caller — passes the same gate.
- `expectedHeadSha` is validated as `^[a-f0-9]{40}$`, matching the repo-wide `headSha` pattern already
  used by `schemas/runtime/*.schema.json`; `expectedWorktreeDigest` reuses the existing
  `sha256:<64-hex>` digest check. This is stricter than the pre-RF5b decoder (any non-empty string) and
  refuses a malformed claim at ingress rather than at comparison time.
- The packaged smoke reaches `resolved` on a real indexed fixture, which the RF4 daemon suite could not:
  `runRefactorScan` reads code facts from the on-disk `.codegraph` index, not from the injectable
  provider. The fixture declares `module.packaged-legacy` with `source.include: ["legacy-shim.ts"]`
  through the same MCP `plan_update` + `apply` ChangeSet path the script already uses — without declared
  ownership the proposal classifies as `model_adoption_required` and no `refactor_proposal`
  recommendation is produced to verify.
- The smoke rebuilds the CodeGraph index twice (after the fixture commit, and after the kill-list file
  is deleted). `evaluateResolution` forces `stale` when `indexedWorktreeDigest` does not bind the
  measured worktree, so without the rebuild the ladder never reaches `resolved`.
- `scripts/packaged-cli-smoke.mjs` restates `digestJson`'s canonical form (sorted keys, JSON, SHA-256)
  to seal the fixture proposal. The script runs the packaged CLI on plain Node and cannot import the
  TypeScript workspace; a drift is not silent, because the daemon refuses the request and names
  `proposalDigest`.
- `catalog.yaml` was regenerated by writing `loadPracticeCatalog().manifest` — the producer that
  `practice-catalog.test.ts` compares against — rather than hand-editing `catalogDigest`. No repo script
  writes that asset; `record:s6:catalog` only reads it.

## Deviations From Plan Or Spec

- **Exit criterion `rg '0.5.0' ... = empty` is not satisfiable inside `allowed_paths`.** Six remaining
  hits are prose comments and one error-message string, not version pins:
  `packages/surfaces/cli/src/main.ts:993`, `packages/surfaces/cli/test/cli.test.ts:2195`,
  `packages/local-runtime/runtime-daemon/src/index.ts:309` and `:911`, and
  `packages/local-runtime/runtime-daemon/test/refactor-recording.test.ts:337` and `:575`. The last two
  live in a file outside `allowed_paths`, and `index.ts:911` is a user-visible message asserted by that
  same out-of-scope suite. The contract's Falsifier ("any live pin still reads 0.5.0") is satisfied;
  the machine criterion is over-broad. The contract was not edited.
- `docs/verification/practice-assets-s6-catalog-readback.json` is outside `allowed_paths` but is written
  by `bun run record:s6:catalog`, which the contract's Goal requires. It was already stale on `main`
  (recorded `catalogDigest` `sha256:a80c896e…` against an asset holding `sha256:b711e2ae…`).
- `recommendations resolve` takes `--id`, `--evidence-digest` and a required `--reason`; the brief's
  sketch omitted `--id`/`--reason`. The smoke uses the real flag set.

## Tradeoffs Considered

| Option | Decision | Reason |
|--------|----------|--------|
| Keep the daemon decoder vs. replace it with the contract validator | Keep both | The decoder rebuilds from declared keys and names the smuggled one (`rawDiff`); the validator proves the rebuilt request. Dropping the decoder would lose the named key, dropping the validator would let CLI and RPC ingress drift. |
| `--recommendation-id` sugar for `refactor verify` | Not implemented | It would be a second parsing path, not one line of sugar, once the two optional claims and the evidence refs are considered. |
| Smoke asserts a rejection envelope vs. reaches `resolved` | Reaches `resolved` | The indexed fixture makes the full ladder decidable, so the weaker assertion was unnecessary. |
| Reword the six historical `0.5.0` comments to clear the sweep | Rejected | Two live outside `allowed_paths` so the sweep would still fail, and rewording accurate historical references to satisfy a grep destroys information. |

## Codex review fixes (2026-09-03)

Four review findings on the committed slice, fixed in the working tree.

**F1 — the resolve gate ignored the worktree digest.** `refactorResolveGate` compared only
`evidence.verifiedHeadSha` to the live HEAD, so a verdict stayed acceptable after uncommitted
edits re-introduced the problem at the same commit. The gate now takes the whole worktree
identity and refuses `verifiedWorktreeDigest` drift with `AC_REFACTOR_STALE` /
`evidence-worktree-drift`, and the pre-append block re-runs the gate over the re-read identity.

The stronger gate changed which refusal the pre-existing F4 guard observes: arming the mutation on
the gate's own snapshot call now trips the gate (the digest is computed after `openSession` reads
HEAD, so the gate sees the new tree), which would have left the pre-append re-read uncovered. The
mutation moved to the pre-append read's own snapshot call so that guard still guards its own path,
and the assertion now names `worktreeDigest`.

**F2 — `executionEvidenceRefs[].locator` was an unbounded string.** A caller could park a raw diff
or a credential in the one free-text field on a record whose envelope promises
`privacy.rawDiffPersisted: false`. The grammar (`REFACTOR_EXECUTION_EVIDENCE_LOCATOR_PATTERN`, 1-256
chars, no whitespace or control characters) and its message
(`REFACTOR_EXECUTION_EVIDENCE_LOCATOR_RULE`) live in contracts and are imported by the daemon
decoder, so the two ingresses cannot drift apart into two shadow parsers.

**F3 — unknown top-level keys were silently dropped.** Both the contract validator and the daemon
decoder rebuild the request from the declared keys, so `expectedWorktreeDigset` removed the
caller's freshness claim instead of failing it. Top-level keys are now closed to
`REFACTOR_VERIFICATION_REQUEST_KEYS` at both layers; the CLI inherits it through the contract
validator it already calls.

**F4 — an invalid `refactor verify` started a daemon first.** `runRefactorCommand` took an
already-obtained client, so the dispatcher's `await runtime()` ran before any flag or JSON check.
It now takes the factory and every subcommand finishes validating before it reaches for a handle.
The packaged smoke's missing-flag step moved after `daemon stop` and asserts the connection and
lock files are still absent afterwards.

Each fix was proved by reverting it and re-running its test: F1 (`refactor-verify.test.ts`
`F1: an uncommitted edit at the same HEAD is worktree drift`), F2 and F3 (contract, daemon and CLI
layers), F4 (`cli.test.ts` `CLI refactor rejects an invalid invocation without ever obtaining a
runtime handle`) all fail on the unfixed code and pass on the fixed code.
